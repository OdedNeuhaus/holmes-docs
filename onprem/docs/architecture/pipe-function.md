## מה זה Pipe Function?

Pipe Function ב-Open-WebUI הוא בעצם פלאגין Python שמתנהג כמו מודל או Agent חדש בתוך ה-UI.

במקור, Open-WebUI נועד לדבר ישירות מול מודל, אבל Holmes הוא Agent ולא מודל. לכן, במקום ש-Open-WebUI ישלח את ההודעה ישירות למודל, הוא יכול לשלוח אותה לפונקציית Pipe, ושם אני מחליט מה לעשות עם הבקשה. ה-Pipe יכול לקרוא ל-API חיצוני, לדבר עם Agent אחר, להריץ לוגיקה משלו, לבצע כמה שלבים ולהחזיר תשובה למשתמש.

מבחינת המשתמש, ה-Pipe מופיע ב-Open-WebUI ממש כמו Model לבחירה, אבל בפועל הוא wrapper סביב [HolmesGPT](./holmesgpt.md).

## מה ה-Pipe Function שלנו עושה

ל-Pipe Function שלנו יש כמה תפקידים, והחשובים שבהם הם:

1. הוא בונה מחדש את ה-conversation history, כדי שתהיה שיחה רציפה עם יותר מ-turn אחד, ושולח ל-Holmes רק הודעות בתפקידים `system`, `user` ו-`assistant`.
2. הוא מנקה מההיסטוריה UI markup ו-reasoning, כמו `<details>` ו-`<think>`, כדי ש-Holmes לא יקבל בחזרה זבל שה-UI עצמו יצר.

## איטרציות ובאגים

עברנו לא מעט איטרציות עם ה-Pipe Function של Holmes. לכאורה הוא "sub-component" במערכת שנראה לא מזיק, אבל הוא יכול להיות תהומי מבחינת חוויית המשתמש.

בעבר חווינו איתו הרבה באגים:

- שיחות שנתקעות באמצע.
- שגיאות לא ברורות.
- תקלות רנדומליות.

היינו צריכים לעבור לא מעט איטרציות יחד עם חברנו Claude כדי להגיע לתוצאה שסיפקה אותנו.

## הכוח של ה-Pipe Function

יש ב-Pipe Function הרבה כוח, וצריך לזכור את זה. למשל, [בעמוד הקודם](./open-webui.md#unused-features) ציינתי שאנחנו לא משתמשים במספיק פיצ'רים של Open-WebUI, כמו Additional System Prompt. אז ה-Pipe Function הוא בדיוק המקום לשחק עם הדברים האלה ולהתאים אותם ל-Holmes.

בדומה ל-UI עצמו, גם ב-Pipe Function אין התעסקות שוטפת, אלא רק בשדרוגי מודל (במידת הצורך) ובכתיבת פיצ'רים נוספים או תיקון באגים. לרוב לא ממש נוגעים בו.

:::warning
ה-Pipe Function הוא ה"רכיב" היחיד (זה לא באמת רכיב, כן?) שלא מנוהל As Code בפרויקט. דוז ניסה פעם לכתוב איזשהו CI/CD שמעדכן את ה-Pipe Function ב-Open-WebUI במידה שהיה בו שינוי ב-Repo (איזה Repo? בהמשך), אבל זה לא ממש עבד. כיום אנחנו פשוט מדביקים אותו ב-UI, וזה לא ממש נשמר הרמטית באף מקום אחר, אלא אם כן אני זוכר מדי פעם להעתיק את הגרסה העדכנית ביותר ל-Repo כדי שיהיה לזה תיעוד.

שווה לטפל בזה.
:::
